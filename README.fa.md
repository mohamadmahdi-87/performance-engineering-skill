# Performance Engineering — مهارت مهندسی عملکرد

**یک مهارت ماژولار برای بررسی و بهبود عملکرد نرم‌افزار با اندازه‌گیری، آزمایش محدود، بررسی عوارض و برنامهٔ بازگشت.**

[English](README.md) · [فایل اصلی مهارت](SKILL.md) · [فهرست ۴۸ بررسی](references/routing.md)

این بسته به سیستم‌عامل، زبان برنامه‌نویسی، فریم‌ورک یا سرویس هوش مصنوعی خاصی وابسته نیست. روش کار عمومی است، اما هر تکنیک فقط در معماری مرتبط اجرا می‌شود؛ مثلاً برنامهٔ خط فرمان الزاماً به CDN یا SSR نیاز ندارد.

**نسخهٔ اولیه: `0.1.0`.** سازگاری عملی با تمام مدل‌ها و ابزارها یا بهبود تضمینی ادعا نمی‌شود. مجوز انتشار و استفادهٔ مجدد هنوز باید توسط مالک تعیین شود.

## چه چیزی داخل بسته است؟

- **۴۸ بررسی:** هر ۳۱ موضوع نسخهٔ قبلی حفظ شده و ۱۷ موضوع برای منابع سیستم، الگوریتم، حافظه، ایمنی، سازگاری، هوش مصنوعی و پردازش داده اضافه شده است.
- **۸ راهنمای فنی:** رابط، فایل‌ها و تحویل محتوا، داده، سرویس، زمان اجرا، پایش، ایمنی و انتشار، هوش مصنوعی و پردازش.
- برای هر مورد: **زمان کاربرد، مراحل اجرا، روش بررسی، محدودیت‌ها و عوارض، روش بازگشت**.
- راهنمای مستقل اندازه‌گیری، مجوز اقدام، تداخل بهینه‌سازی‌ها و بازیابی.
- قالب گزارش و آزمایش؛ مثال استفاده؛ اعتبارسنج ساختار و تست‌های آن.

متن عملیاتی انگلیسی است تا استفادهٔ عمومی و اشتراک‌گذاری آسان‌تر باشد. این README راهنمای فارسی استفاده است، نه نسخهٔ دوم دستورالعمل‌ها؛ بنابراین لازم نیست ایجنت هر دو زبان را بارگذاری کند.

## استفاده

۱. کل پوشه را با نام **`performance-engineering`** نگه دارید؛ کپی‌کردن `SKILL.md` به‌تنهایی کافی نیست.

۲. اگر ابزار شما از Agent Skills پشتیبانی می‌کند، پوشه را در مسیر مهارت‌های همان ابزار قرار دهید. مسیر نصب در همهٔ ابزارها یکسان نیست؛ از راهنمای همان ابزار استفاده کنید.

۳. اگر ابزار فقط متن می‌گیرد، `SKILL.md`، فایل `references/routing.md` و بخش‌های مرتبط را به آن بدهید. اگر دسترسی اجرایی ندارد، خروجی صرفاً بررسی متنی یا برنامهٔ آزمایش است، نه تأیید واقعی عملکرد.

۴. محدودهٔ کار و اجازه‌ها را مشخص کنید. حالت پیش‌فرض فقط **audit** است؛ ویرایش یا اجرای دستور خودکار مجاز فرض نمی‌شود.

### نمونهٔ شروع امن

```text
از مهارت performance-engineering در حالت audit استفاده کن.
فقط مسیر کندِ ورود فایل را بررسی کن؛ هیچ فایل، وابستگی یا تنظیماتی را تغییر نده.
هیچ دستور، درخواست شبکه یا آزمایشی اجرا نکن.
حداکثر سه فرضیهٔ دارای شاهد، معیار اندازه‌گیری و برنامهٔ آزمایش محدود بده.
موارد نامرتبط را از مواردی که شواهد کافی ندارند جدا کن.
```

### اجرای اصلاح تأییدشده

```text
فقط آزمایش محلی‌ای را اجرا کن که قبلاً تأیید کرده‌ام.
تغییر کد همان بخش و تست مرتبط مجاز است؛ کار فعلی من را حفظ کن.
قبل از اجرای تست، اثرات جانبی دستورها را بررسی کن.
محدودیت: پنج دقیقه، یک پردازش، دادهٔ ساختگی، بدون شبکه و نصب وابستگی.
مهاجرت داده، سرویس پولی، انتشار، commit و push مجاز نیست.
صحت خروجی، مصرف منابع و نتیجهٔ قبل/بعد را گزارش کن؛ نتیجهٔ اندازه‌گیری‌نشده نساز.
```

## کاهش مصرف توکن چگونه است؟

ایجنت ابتدا فقط فایل اصلی و فهرست مسیرها را می‌خواند؛ سپس راهنمای مرتبط یا بخش موردنیاز را بارگذاری می‌کند. READMEها، مثال‌ها و ابزار اعتبارسنج برای اجرای عادی لازم نیستند. شناسه‌های `P01` تا `P48` برای ارجاع دقیق و نگهداری گزارش کوتاه استفاده می‌شوند.

درصد ثابت یا عدد تضمینی برای کاهش توکن وجود ندارد؛ مدل، ابزار، روش خواندن فایل و اندازهٔ گزارش اثر دارند. بررسی کامل ۴۸ مورد طبیعتاً از بررسی یک مسیر هزینهٔ بیشتری دارد.

## وضعیت‌های گزارش

| وضعیت | معنی |
|---|---|
| `unknown` | شواهد کافی نیست |
| `not-applicable` | با معماری بررسی‌شده ارتباط ندارد |
| `pass` | معیار مشخص در محدودهٔ بررسی شاهد کافی دارد |
| `needs-work` | نیاز به اقدام دارد |
| `needs-approval` | اقدام به اجازهٔ مشخص نیاز دارد |
| `changed-unverified` | تغییر انجام شده ولی تأیید کامل نشده |
| `verified` | صحت و نتیجه در شرایط اعلام‌شده تأیید شده |
| `reverted` | تغییر مشخص واقعاً بازگردانده شده |

## بررسی ساختار بسته

خود مهارت فقط فایل متنی است. ابزار اختیاری بررسی بسته به Python 3.10 یا جدیدتر نیاز دارد و از کتابخانهٔ استاندارد استفاده می‌کند؛ شبکه و نصب پکیج لازم ندارد. پس از خواندن اسکریپت، از داخل پوشه:

```text
python scripts/validate.py
python -m unittest discover -s tests -v
```

بسته به سیستم ممکن است نام اجراکننده `python3` یا `py -3` باشد. این ابزار لینک‌های داخلی و ساختار را بررسی می‌کند؛ صحت تمام توصیه‌ها، رفتار تمام ایجنت‌ها یا امنیت کامل پروژه را تضمین نمی‌کند. تعریف CI چندسیستمی هم به‌تنهایی به معنی اجرای موفق آن نیست.

نتیجهٔ اجرای محلی: اعتبارسنج و **۲۵ تست** در Linux با Python 3.11.16 موفق بودند. جزئیات و محدودیت‌ها در [گزارش اعتبارسنجی](docs/VALIDATION.md) آمده است. CI در گیت‌هاب و سازگاری با میزبان‌های هوش مصنوعی هنوز اجرا و تأیید نشده‌اند.
